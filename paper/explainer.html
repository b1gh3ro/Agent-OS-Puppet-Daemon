01 — The story

An AI that watches a screen

This paper is about a certain kind of AI program — an agent — that controls a computer the way a person does. It looks at the screen as a picture, moves the mouse, types, clicks. It doesn't get a special data feed from the apps it uses; it only sees the pixels, exactly what you'd see. You give it a goal in plain English and it works toward it, one action at a time.

Now picture a very ordinary task: “Wait for my colleague to reply, then act on it.” The reply arrives in thirty minutes. The actual work — read the message, write an answer, send it — is maybe four actions. The other thirty minutes are spent doing nothing.

That “doing nothing” is the whole story. It sounds free. It isn't.

02 — Why waiting costs money

The AI can't just “sit there”

Here's the catch that most people never think about. These agents are built as a loop: look at the screen → think → take one action → repeat. There is no step in that loop called “wait.” The only way for the agent to let time pass is to keep taking actions — so it takes the emptiest action it can: look again.

Take a screenshot. Ask the AI, “has anything changed?” No. Wait a moment. Take another screenshot. Ask again. No. Again. No. This is called polling, and it's how an agent “waits” when nothing lets it truly pause.

The expensive detail

Every one of those “has anything changed?” checks is a full request to the AI model — the slow, costly part. A computer checking a file does this millions of times a second for free. But when the thing doing the checking is a large AI model, each check costs real money and real seconds.

So the cost of waiting grows with how long you wait. Wait twice as long, pay twice as much — to learn, over and over, that nothing happened yet.

Browsers solved this problem years ago. Tools like Playwright can say “wait until this button appears” and quietly block until it does — no wasted checks. But that trick needs access to the page's underlying structure. An agent that only sees pixels has no structure to query. The clean solution exists everywhere except for exactly the agents that need it most.

03 — The idea

Waiting is an action too

The paper's core insight is one sentence: waiting is itself an action — and unlike other actions, the AI doesn't need to be awake while it happens.

Nothing requires the expensive model to be present while time passes. If a cheap watcher can keep an eye on the screen and only wake the AI when something actually changes, then the number of costly model calls stops depending on how long you wait. Thirty seconds or three hours — it's still just one wake-up when the moment arrives.

The paper builds and compares three different ways to wait, and is honest about when each one wins.

The third one — watch for change — is the paper's new contribution: a pixel-level version of the browser trick, for agents that only see pixels.

04 — How the watcher works

Noticing that the screen changed

The watcher is deliberately dumb, because dumb is cheap. It shrinks the screen to a tiny 240×152 grey thumbnail and, once a second, compares it to the previous one. A pixel “counts” as changed only if it shifts noticeably. The screen as a whole counts as changed only if more than 0.4% of pixels moved at once.

That threshold is chosen to be eager but not jumpy: a new chat bubble popping up should trip it; a blinking text cursor or a nudged mouse pointer — just a few pixels — should not. When it trips, it wakes the AI exactly once, hands over one fresh screenshot, and the AI decides what to do. No AI model runs at all during the wait itself.

05 — The honest catch

What happens on a busy screen

The “watch for change” idea has a real weakness, and the paper leads with it rather than hiding it. The watcher can't tell a meaningful change from a meaningless one. It only knows “pixels moved.”

On a calm screen this is perfect — nothing moves until the thing you're waiting for happens, so the AI wakes up exactly once. But put a ticking clock, a scrolling log, or a video in the corner, and the watcher keeps waking the AI for changes it doesn't care about. Each false alarm is a full, paid model call. In the worst case — constant motion — it degrades right back into expensive polling, or even worse.

The claim, stated fairly

“Watch for change” is cheap on a quiet screen, and gets more expensive as the screen gets busier. That trade-off — where exactly the switch from cheap to expensive happens — is the thing the experiments are built to measure. It's the contribution, not a footnote.

06 — The machine

How it was built

The setup has three parts, kept deliberately simple because the plumbing isn't the point — the waiting idea is.

  • A sandbox. A throwaway Linux desktop running inside Docker — its own isolated screen, keyboard, and mouse, with no access to the real computer's files. This is the screen the agent sees and controls.
  • A brain. The part that runs the look–think–act loop, powered by Google's Gemini “computer-use” model. It's what decides where to click and, now, how to wait.
  • A daemon. A small background service that hands out jobs, keeps a record of every step, and — crucially — runs the cheap “watch for change” loop outside the expensive model.

One detail matters more than it seems: the agent only gets a screenshot when it asks for one — it isn't watching a live video. That's exactly why plain polling is so costly, and it's true of essentially every pixel-based agent, not just this one.

07 — The experiment

How the tests are run

To compare the three waiting styles fairly, the experiment builds little scenes where exactly one thing happens, at a moment the test controls. Because the test itself triggers that event and notes the instant it did, the agent's reaction time can be measured rather than guessed.

The eight scenes

Each scene shows the agent a screen and asks it to report a hidden codeword the moment it appears — a small trick that stops a lazy agent from just claiming “done” without ever looking. The scenes range from perfectly calm to deliberately chaotic:

  • Three calm scenes — a dialog box pops up, a build finishes in a terminal, a download completes.
  • Four noise-ladder scenes — the same wait, but with increasing background fidget (a spinner, a ticking clock, a scrolling log), from barely-there to overwhelming.
  • One control — where nothing ever happens, to see what each strategy costs when the thing you're waiting for simply never arrives (and to catch an agent that hallucinates seeing something).

The noise ladder

“Busy” isn't judged by eye — it's measured, as a multiple of the watcher's 0.4% threshold. This is the clever bit: two scenes sit below the line (the watcher rightly ignores them) and two sit above it (false alarms begin). The ladder pins down where cheap turns into expensive.

Keeping it a fair fight

A few rules make the comparison honest:

  • The instructions never hint at a strategy. The agent is simply told “watch and report.” Which waiting tool it's allowed to use is controlled behind the scenes — so the test measures the tool, not a nudge in the wording.
  • Four setups run against each scene: poll-only, sleep-only, watch-only, and a fourth free-choice setup where the agent is handed both tools, described neutrally, to see which it picks on its own.
  • The agent can't cheat. Its shortcut tools (like opening a terminal to script its own timer) are removed, forcing it to actually watch the screen.
  • Time is measured with an internal stopwatch, never wall-clock. On a laptop that sleeps, wall-clock lies wildly — in the real deployment logs, host sleep inflated the apparent time by 22 hours. The internal clock is immune.

The prediction, written down before the tests were run: on the calm scenes, watch should be both cheap and fast — winning on every axis. As the noise ladder climbs past the threshold, watch should start racking up false alarms and drift toward the cost of polling. Sleep should stay cheap but react late. Poll should react quickly but cost the most. If the prediction is wrong, the paper commits to reporting that too.

In one sentence

Today's AI agents can't say “wait” — so they wait by repeatedly, expensively looking. Move the watching to a cheap process outside the model, and the cost of doing nothing stops growing with the clock. The interesting part isn't the trick; it's knowing exactly when the trick stops working.
